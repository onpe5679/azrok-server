> **크기 불일치 단서는 기각됐다 (2026-07-30, VERIFIED).**
> 이 문서가 남긴 마지막 단서 `canvas 640x480` vs `gl.drawingBuffer 1024x768` 은 결함이 아니다.
> 두 값은 **서로 다른 두 캔버스**의 값이었다 — 같은 시점에 함께 찍어 확인했다:
>
> | 요소 | attr(백킹) | CSS | 위치 |
> |---|---|---|---|
> | `#canvas` (SDL source) | 640x480 | 1024x768 | 429,232 |
> | `#d3d9web-canvas` (D3D output) | 1024x768 | 1024x768 | 429,232 |
>
> #532 가 정적으로 예고한 오버레이 계약(`d3d9web-runtime.js:598-630`, `:1070-1095`)과 정확히 일치한다.
> 나는 `getElementById('canvas')`(source)를 재면서 WebGL 컨텍스트는 output 것이라고 봤다.
> **크기를 강제로 맞추는 수정은 하지 말 것** — 입력 640→1024 변환 계약이 깨진다.
> 현재 1순위 후보는 #532 의 "navy CLEAR 가 남고 이후 draw 가 덮지 못한다" 이다.

# 530 광장 파란 화면 — GL 파이프라인 실측 (2026-07-30)

날짜: 2026-07-30
선행: #529(광장 진입·상호 가시성)
증상: 광장에서 엔터(채팅) 입력 후 화면이 **단색 남색 RGB(0,0,128)** 이 되고 복구되지 않는다.
사용자 보고: OX 퀴즈 진입에서도 같은 계열로 화면이 나갔다.

## 1. 크래시가 아니다 (VERIFIED)

- Present 카운터가 계속 증가한다(FPS 25~33 유지).
- 게스트 로그에 에러 없음. `D3D9WEB_FPS_SAMPLE` / `D3D9WEB_ASYNC_RING_FRAME` 이 정상 주기로 계속 찍힌다.
- 서버 `/api/overview` 상 세션은 살아 있고 `room=plaza` 소속을 유지한다.

## 2. 순수 클라이언트 문제다 (VERIFIED)

엔터 입력 시 **서버로 나가는 패킷이 하나도 없다.** 최근 600줄에 채팅 `C2S 0x0068`(18B+)도
`S2C 0x006A` 도 없다. 즉 서버 상태 전이와 무관한 클라이언트 렌더링 문제다.

## 3. GL 파이프라인은 구조적으로 정상이다 (VERIFIED)

WebGL 프로토타입을 감싸 실측했다(재빌드 없음).

```text
drawsPerFB_perSec   { fb1: 2907 }
clearsPerFB_perSec  { fb1: 77 }
blitPairs           { "read fb1 -> draw fb0": 205 }   (8초 창 = 약 26/s, fps 와 일치)
lastBlitRects       src [0,0,1024,768] -> dst [0,0,1024,768]
```

프레임 내 호출 순서(C=clear, D=draw, B=blit, 숫자는 draw 프레임버퍼):

```text
C:1  D:1 ×90   C:1  D:1 ×17   C:1  D:1 ×8   B:0
```

즉 **fb1 을 지우고 → fb1 에 약 115회 그리고 → fb1 을 화면(fb0)으로 복사**한다.
순서·대상 모두 정상이다. 다음 세 가설은 실측으로 **전부 기각**했다.

| 가설 | 판정 | 근거 |
|---|---|---|
| 최종 합성 패스가 멈췄다 | **기각** | `blitFramebuffer` 가 초당 22~26회 정상 호출됨 |
| draw 대상 FBO 와 blit 소스 FBO 가 다르다 | **기각** | 둘 다 fb1 |
| 프레임 내 순서가 뒤집혔다(blit 이 draw 보다 먼저) | **기각** | 트레이스상 draw 가 blit 보다 선행 |

기본 프레임버퍼 픽셀은 전 구간 균일하다: `(20,20)=(320,240)=(600,450)=0/0/128`.
blit 이 fb1 을 그대로 복사하므로 **fb1 자체가 남색**이라는 뜻이다.

## 4. 확인된 이상 — 캔버스와 드로잉버퍼 크기 불일치 (VERIFIED)

```text
canvas 속성      : 640x480
gl.drawingBuffer : 1024x768
blit 사각형      : src/dst 모두 [0,0,1024,768]
```

정상 PatHouse 구간에서는 백킹이 **640x480** 이었다(#529 재현 구성 참조).
파란 화면 상태에서만 드로잉버퍼가 1024x768 로 벌어져 있다.
blit 은 1024x768 기준으로 수행된다.

**INFERRED(미확정)**: 해상도 전환(640x480 → 1024x768)이 일어났는데 캔버스 속성과
드로잉버퍼가 어긋났고, 그 결과 화면에 남는 것이 클리어 색뿐일 가능성.
다만 draw 는 fb1 에 계속 들어가고 blit 도 정상이므로, "그려진 내용이 왜 남색인가" 는
아직 설명되지 않았다. 마지막 8회 draw 가 전체 화면을 덮는 패스일 가능성도 배제되지 않았다.

## 6. 측정 방법 (재사용 가능)

브라우저 재빌드 없이 `WebGL2RenderingContext.prototype` 을 감싸 계측했다.
`drawArrays`/`drawElements`/`clear`/`blitFramebuffer`/`bindFramebuffer` 를 후킹하고,
WebGL2 는 READ/DRAW 프레임버퍼 바인딩이 분리돼 있으므로 **두 바인딩을 따로 추적해야 한다**
(하나로 합치면 blit 직후의 바인딩 때문에 draw 대상이 오분류된다).
스크립트: `scratchpad/gl_census.ps1`, `fbo_census.ps1`, `fbo_identity.ps1`.
