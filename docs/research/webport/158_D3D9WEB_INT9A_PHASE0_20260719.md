Date: 2026-07-19

## Question

Can a 32-bit Windows PE guest push a D3D9Web command index and arguments,
execute `CD 9A`, reach a BoxedWine host callback, and receive the callback's
EAX result without inventing a new decoder opcode or installing emsdk?

## Minimal implementation

**VERIFIED source/build:** the existing `Int9A` decoder slot is reused only
when `BOXEDWINE_D3D9WEB` is defined. Both execution paths are wired:

- JIT/native: `common_int9A` -> `callD3D9Web`
- interpreter/Emscripten: `normal_int9A` -> `callD3D9Web`

`BOXEDWINE_D3D9WEB` takes priority over `BOXEDWINE_VULKAN` in the dedicated
native proof build. The browser build defines no Vulkan backend, so the slot is
otherwise unused there. No decoder enum, JIT code generator, OpenGL dispatch
table, or Vulkan implementation was changed.

The Phase-0 dispatcher accepts index 0, reads `peek32(1)` and `peek32(2)`, logs
them, and returns `EAX=0x1234`. The x86 guest pushes:

```text
arg2 = 0x11223344
arg1 = 0xA1B2C3D4
index = 0
CD 9A
```

`dumpbin` verifies the guest is machine `0x14C` and contains:

```asm
0040101F: CD 9A    int 9Ah
```

## Dynamic result

**VERIFIED on the rebuilt native BoxedWine x64 Release/JIT executable:**

```text
D3D9WEB_PHASE0 index=0 arg1=0xA1B2C3D4 arg2=0x11223344
D3D9WEB_GUEST index=0 arg1=0xA1B2C3D4 arg2=0x11223344 eax=0x00001234
EXITCODE=0
```

This proves the PE guest -> BoxedWine CPU/JIT -> host callback -> EAX return
round trip and the stack offsets. It also confirms MSVC `_emit 0xCD,0x9A`
encoding, so MASM literal syntax is no longer an open question.
