# 160 D3D9Web WebGL2 Phase 3 — shared-canvas triangle

Date: 2026-07-19

> **D3D9 COM follow-up completed by 161.** This document remains authoritative
> for the direct synthetic WebGL2 command proof.

## Result

**VERIFIED in the local browser:** a synthetic 32-bit PE guest issued command
index 1 through the custom BoxedWine `INT 0x9A` bridge. The Emscripten callback
obtained WebGL2 on BoxedWine's existing 800x600 canvas, cleared it, compiled
and linked GLSL ES 3.00 shaders, and drew one triangle.

The guest received the callback success value `EAX=0x00003001` and the batch
file reported exit code 0:

```text
D3D9WEB_PHASE3_GL webgl2=1 triangle=1 canvas=shared size=800x600
D3D9WEB_PHASE3_GUEST eax=0x00003001
D3D9WEB_PHASE3_EXITCODE=0
```

The first launch marker was logged at `00:29:02.175Z`; the WebGL success marker
arrived at `00:29:05.772Z`. The retained DOM state has one canvas and no
overlay (`canvasCount=1`, `overlay=false`). The fallback overlay path therefore
was not used in this run.

## What this proves

1. The custom guest PE -> BoxedWine callback -> JavaScript path from 158/159
   can drive browser WebGL2, not only exchange scalar test values.
2. SDL's existing browser canvas can host the WebGL2 context in this harness;
   a second overlay canvas is not intrinsically required.
3. Shader compilation, buffer upload, `drawArrays(TRIANGLES, 0, 3)`, pixels,
   and a synchronous guest return all complete in one run.

## What this does not prove

- No D3D9 COM object or vtable is involved yet.
- `Direct3DCreate9`, `IDirect3D9::CreateDevice`, and
  `IDirect3DDevice9::{Clear,BeginScene,EndScene,Present}` are not connected.
- No Azrok render call has reached this bridge.
- This does not measure Azrok browser FPS.
