# 659 — 운영 관제실 UI/UX 개편 (2026-10-26)

## 변경 범위

운영자가 계정·캐릭터를 찾고 수정하는 작업을 기본 화면으로 재구성했습니다.
기존 패킷 중심 관제 화면은 `/debug`에 보존하고 `/`, `/index.html`, `/admin`은
새 `azrok_operator_page.py`를 제공합니다. 게임 바이너리·게임 규칙·캐릭터
저장 형식은 변경하지 않았습니다.

- 큰 시스템 글꼴, 밝은 작업 영역, 구분되는 메뉴와 상태 표시를 사용합니다.
- 계정·캐릭터 / 서버 현황 / 접속·채팅 기록 / OX 운영으로 화면을 분리합니다.
- 닉네임을 우선 표시하고 검색·활동순·접속 중·캐릭터 보유 필터를 제공합니다.
- 캐릭터 상세는 한 패널의 기본 정보/인벤토리/기록 탭으로 정리합니다.
  성장단계는 이름으로 표시하고 스탯·원본 퀘스트 데이터는 접어 둡니다.
- 펀콘과 아이템을 함께 수정하고 변경 요약을 확인한 뒤 한 번에 저장합니다.
  미저장 종료 보호, 저장 중 입력 잠금, revision 충돌 시 입력 보존과 최신
  저장 다시 불러오기, 이름 확인을 거치는 백업 삭제를 제공합니다.
- 작은 화면에도 메뉴 이름과 저장 버튼을 유지합니다. 확인 대화상자는
  브라우저 기본 confirm 대신 화면 안에서 동작하며 키보드 초점을 제한합니다.
- 서버·OX 화면은 열어 둔 동안 10초마다 갱신합니다. 기술용 JSON을 그대로
  보여주는 대신 가동 상태, 접속 수, 방·문제·참가자·생존자·순위를 표시합니다.

## API와 운영 범위

기존 `/api/admin/character`의 온라인 수정 금지·revision 검사·백업 규칙은
유지합니다. `/api/admin/history`에서 key를 생략하면 전체 운영 이력을
종류와 검색어로 조회합니다. 기존 캐릭터별 조회는 동일합니다.
이력은 기존 안전한 journal의 최근8MiB/최대200건이며 잘림 여부를 표시합니다.
이전 기록을 새로 만들어 내거나 수집 범위를 확대하지 않았습니다.

배포 백업: `rollback/operator-ux-20261026/`.
