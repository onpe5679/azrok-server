> not establish safety in active Plaza/mode 1.  A later x32dbg trace proved

## Result

One S2C `0x0065` packet with an empty payload was sent through the normal server control path in a stable state-1 OX session. It was safe and externally inert.

Evidence capture: `captures/packets_20260717_063259.txt`, sequence 116.

## Controlled conditions

- C2S self transition already completed with mode `01`.
- State before the probe: scene 111, phase 5, self ID 1, flags `0/1/0`, logic `2`, Nexus 40.
- No previous `0x0065` existed in the capture.
- The packet used `/api/send -> inject -> _emit`, with `origin=manual`.
- No executable or memory changes were made.

## Observation

After seq 116 S2C `0x0065` empty:

- four C2S/S2C `0x0016=00` heartbeat pairs completed normally;
- no unknown C2S opcode appeared;
- C2S `0x00C8` did not repeat;
- all exposed watches remained identical;
- the client connection and responsive Azrok process remained alive;
- Windows recorded no Azrok crash event.

The recovered static path is state-1 dispatcher `0x00613740` to handler `0x00615B20`, then remote-list flush/finalize `0x0050D5D0`. Runtime instruction-pointer confirmation was not attempted because the experiment prohibited breakpoints and tracing; x32dbg without those mechanisms cannot prove a past handler call.

## Implication

`0x0065` is confirmed as a low-risk remote-container maintenance packet, not a self-state or ready-state trigger. The next lowest-risk isolated probe is empty S2C `0x0066`, which skips the `0x1A`-byte record loop and only runs its trailing remote-list finalizer.
