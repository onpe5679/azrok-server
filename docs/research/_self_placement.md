# self 재배치 — 패킷·메모리 양쪽 계약 확정 (2026-07-18)

INDEX 58 행의 미해결 항목을 닫는다:
> "콘텐츠 탐색 전략 … **self 재배치 packet/function은 아직 NOT VERIFIED** (74)"

근거는 `HandleS2C_0064_ApplyAuthoritativeSelf` @ `0x00615650` 의 **디스어셈블 본문**이다
(디컴파일이 `thunk_FUN_...` 로 뭉갠 부분을 명령어 수준에서 다시 읽었다).
등급: **VERIFIED** = 명령어 직접 확인, **INFERRED** = 추론.

---

## 1. S→C `0x0064` 페이로드 맵 — VERIFIED

| off | 크기 | 필드 | 근거(명령어) |
|---|---|---|---|
| `+0x00` | 1 | **entry_kind** — `0x00`/`0x0A`/`0x0B`/`0x14` 만 처리, 그 외 **전체 no-op** | `0061565f`~`00615687` 4중 비교 후 `JMP 0x006159f4`(즉시 종료) |
| `+0x01` | 4 | self_id | `006156bf MOV ECX,[EAX+0x1]` |
| **`+0x06`** | **4** | **pos_x_raw** | `0061570f MOV ECX,[EAX+0x6]` |
| **`+0x0a`** | **4** | **pos_y_raw** | `00615724 MOV ECX,[EAX+0xa]` |
| `+0x12` | 1 | selector_0 | `0061568f MOVZX ECX,[EAX+0x12]` → `CALL 0x004db100(0, v)` |
| `+0x13` | 1 | selector_1 | `006156a7` → `CALL 0x004db100(1, v)` |
| `+0x14` | 7 | tail (dword + word + byte 를 스택으로 복사) | `006157af`~`006157cc` |
| `+0x1a` | 1 | **room_domain** — `< 0x1E` 면 로컬 리셋 게이트 | `006157d8 CMP ECX,0x1e / JGE` |

## 2. ★ 좌표 인코딩 = `raw << 10` — VERIFIED

```c
FUN_004edde0(x) { return x << 10; }     // 0x004da656 은 이 함수로 가는 썽크
```
```asm
0061570f: MOV ECX,[EAX+0x6]      ; x_raw
00615713: CALL 0x004da656        ; <<10
0061571e: MOV [EDX+0x10],EAX     ; selfActor->x
00615727: MOV ECX,[EAX+0xa]      ; y_raw
00615728: CALL 0x004da656        ; <<10
00615733: MOV [EDX+0x14],EAX     ; selfActor->y
00615738: PUSH 0x0 / CALL        ; 0<<10
00615743: MOV [ECX+0x1c],EAX     ; selfActor->+0x1c = 0
```

→ **와이어는 월드 단위 정수, 내부는 `×1024` 고정소수점**이다.
`WMB` 에서 읽은 좌표(예: `foodmaker_01(-722,416)`)는 **와이어 값 그대로** 넣으면 되고,
**메모리에 직접 쓸 때는 `<<10` 한 값**을 써야 한다.

## 3. self actor 접근 경로 — VERIFIED

```asm
006156ee: MOV EAX,[EBP-0x4]      ; 핸들러 this
006156f1: MOV ECX,[EAX+0x4]      ; this->field_4
006156f4: CALL 0x004d7fa0        ; 썽크
006156f9: MOV [EBP-0x58],EAX     ; 중간 객체
006156ff: MOV EDX,[ECX]          ; vtable
00615704: MOV EAX,[EDX+0x8]      ; vtable[2]
00615707: CALL EAX               ; → self actor
00615709: MOV [EBP-0x8],EAX
```
`selfActor = (this->field_4 → 0x004d7fa0)->vtable[2]()`

**필드 오프셋 (VERIFIED)**: `+0x10`=X, `+0x14`=Y, `+0x1c`=(0 으로 초기화되는 축),
`+0x34` 에 상수 `0xAE0200` 기록(`0061578c`).

## 4. 배치 유효성 검사와 폴백 — VERIFIED

```asm
00615966: CALL 0x004d8fd6 ... 00615973: CALL 0x004e092a   ; 검사
0061597b: TEST EAX,EAX
0061597d: JZ  0x006159e9                                   ; 0 이면 통과
0061597f: PUSH 0xfffffe0c ; -500   <<10  → [EBP-0x14]
0061598f: PUSH 0xfffff7a8 ; -2136  <<10  → [EBP-0x10]
```
- 검사 반환이 **0 이 아니면 막힌 것**이고, 좌표가 **`(-500, -2136)`** 로 강제된다.
- 즉 임의 좌표를 넣어도 조용히 폴백되므로, **폴백 좌표가 관측되면 "그 지점이 막혔다"는 신호**다.

## 5. 두 가지 재배치 수단 — 용도가 다르다

| | **패킷 `S→C 0x0064`** | **메모리 직접 쓰기** |
|---|---|---|
| 부작용 | 방/도메인 갱신, 씬 전환(`0x0A`→`0x2E`, `0x0B`→`0x2F`), `GameManager_CloseLoadingScreen()` | **없음. 좌표만** |
| 유효성 검사 | **있음**(막히면 폴백) | **없음**(벽/지면 아래 박힐 수 있음) |
| 적용 범위 | self actor 가 유효한 씬 | 액터가 존재하면 어디서든 |
| **PatHouse** | **위험 — 씬 이탈 가능. 검증 전 사용 금지** | 안전(부작용 경로를 안 탐) |
| 원본성 | 원본 서버가 실제로 쓰던 경로 | 분석 도구 |

**권고**
- **Plaza·방 진입** → `0x0064`(entry_kind `0x00`). 원본 경로라 자연스럽다.
- **PatHouse 내부 이동(요리 가구 등)** → 메모리 직접 쓰기. `0x0064` 는 방/씬 로직이 붙어 있어
  집 안에서 쏘면 밖으로 튕길 수 있다.
- 메모리 쓰기는 유효성 검사를 우회하므로 **가구 좌표가 아니라 그 앞의 통행 가능 지점**을 쓰고,
  쓴 뒤 한 프레임 지나 캡처로 확인한다.

> ### ⚠ 2026-07-18 경고 — 계측이 관측 대상을 망가뜨린 전례
> 위 "메모리 직접 쓰기" 권고를 **Frida 로 구현할 때는 주의해야 한다.**
> 같은 날 동적 트랙에서 **오븐 클릭 크래시의 원인이 Frida 자체로 확정**됐다:
> 서버 패킷 전송 **전에** 발생한 로컬 접근 위반이었고, WER 모듈 목록에 `frida-agent.dll`
> 이 실제 로드돼 있던 직접 기록이 남았다. 프리다·x32dbg·자동클릭을 전부 뺀 clean 세션에서
> 같은 조작을 하니 **크래시 없이 요리 제작 경로가 정상 동작**했다(재료 `2→1` 저장 확인).
>
> → 재배치를 위해 계측을 붙이는 순간, **관측하려던 버그가 계측 때문에 생긴 것인지 구분할 수 없게 된다.**
> 가능하면 (a) 자연 조작으로 되는 것은 자연 조작으로 하고, (b) 계측이 꼭 필요하면
> **계측 없는 baseline 을 먼저 확보**한 뒤 비교하라. 크래시가 나면 계측을 먼저 의심할 것.

## 6. 남은 것 — NOT VERIFIED

- 핸들러 `this`(= `[EBP-0x4]`, 진입 시 ECX)에 해당하는 **런타임 전역 포인터**를 아직 특정하지 않았다.
  Frida 로 쓰려면 이 체인의 시작점이 필요하다. `0x004d7fa0` 썽크의 목적지와 `vtable[2]` 의 실명을
  확인하면 닫힌다.
- PatHouse 에서 self actor 가 유효한지 자체가 **미확인**이다(INDEX 54 의 "유효 self actor" 는 Plaza 조건).
  메모리 쓰기 전에 액터 포인터가 널이 아닌지부터 봐야 한다.
